## 最终流程（已验证）

```
① 生图：角色设定图（PC-98 画风）→ 每句歌词一张关键帧（按 HUD 留白构图）
② Seedance：关键帧当参考图 + 对应音频切片 → 5 秒左右的动作片段（少动作、卡重拍）
③ 测偏移：Whisper 词级时间戳 / findoffset.py → 片段第 0 秒对应原曲几秒
④ 合成：抠图换背景（live98）、代码镜头、锁 16 色调色板 + Bayer 抖动 + 扫描线（pc98ify）
⑤ 出片：mv.py 按原曲时间轴拼镜头（partN.py 里配置），画 HUD / 歌词 / 冲击字，合成原曲音轨
```

## 核心经验

### 1. 画风必须在生图阶段就定死，代码只做收尾（最重要的一条）

- 第一轮拿**现代萌系厚涂**底片（柔光、渐变、暗舞台）硬转 16 色，结果出现"豹纹"色斑，脸发灰（见 `成片/02`）。
- 于是写了 trace98 想在代码里补救：抠图、分材质、手工调色板重新填色（`成片/03`），好了一些，但头发斑块、眼睛简陋的问题解决不了。**这是在错的地方补。**
- 对比参考视频才发现：它的底图本来就是 90 年代 PC-98 画风（平涂、硬阴影、成束头发），代码只做量化、网点和扫描线，几乎没有损失。
- 我们把角色设定图重做成 PC-98 风（v2）以后，同一个 pc98ify 转出来就干净了。**原图不对，后面怎么修都修不好。**

**PC-98 风底图的要求**：头发画成几大束（不要细发丝）、粗墨线、每色两阶硬阴影、不要渐变和喷枪、**白衣服用冷淡紫灰阴影**（拉开冷暖对比）、纯色背景、**不要网点和纸纹**（会和代码加的 Bayer 网点打架）。

### 2. 参考视频是怎么做的（拆解）

- 分工：AI 负责人物和动作（片尾致谢是 "MOTION REFERENCE: Seedance 2.5"），代码负责统一画风、HUD 和特效，外加**大量纯代码镜头**：loss 曲线、属性面板（MATH ∞ / CODE 2.3E11）、RPG 战斗菜单（ROKO'S BASILISK appeared! → FIGHT / PRAY / OFFER GPU）、聊天窗口、标着 "FRAGILE · CONTAINS AGI" 的木箱。
- **有限动画**：视觉小说式的静态 CG 加眨眼、变色、反光这类小动作。AI 视频最怕大幅运动，这种画风正好把弱点藏住。
- **人物动画是混用的，不是一种办法铺到底**（09-29 逐帧拆全曲后的修正；09-28 第三阶段曾认为「人物全是原画 + 停帧 + 代码位移，不是连续视频」，只对了一部分）：
  - 主角跳舞：视频模型的连续动作，按一拍二播放（每秒 12 张），背景和特效逐帧走。
  - 停住的画：确实有，例如指镜头眨眼那一镜（35 帧只换了 2 次画面），用在表情、特写这类镜头。
  - 身体定住、只有头发和手在动：视频模型直接就能生成，不一定是后期合成的。
  - 跳起那种力量感：不是代码把图往上挪，而是在最高点停久一点，落地时硬切近景、闪白、砸大字。
  - 配角跳舞：两张姿势每拍来回换。
  - 这几种做法见核心经验 8。

**参考片的节奏**：前 38 秒切了 27 次，平均 1.36 秒一镜；高潮句一个词一个镜头，一句歌词至少两个景别。
- **一句歌词一个镜头，每句都有一个视觉双关**，2–4 秒一切；竖排日文大字（死神の目、最適化、特異点）；贯穿全片的 P(DOOM) 仪表；视觉小说对白框里打字机式出现的歌词。
- 对照 PDoomVideo（github.com/JohnHeibel/PDoomVideo）：那个是 Claude **真的用 p5.brush 画了每一帧**，但角色都很简单（Clawd 方块 + 简笔研究员）。**代码画的角色简单但可控，AI 画的角色精细但难控。**

### 3. Seedance 实测行为

- 输出 **854×480、5.04 秒**（默认 5 秒档），画面底部中间有 "AI生成" 水印。
- **它会裁掉音频开头**：传 5.4 / 5.9 秒的音频，第一次裁了 0.29 秒，第二批丢了 0.5–1 秒。**09-28 用 API 传 6 秒音频（480p）也照样裁了约 0.94 秒**（四条都这样，没有重唱）。所以片段第 0 秒 ≠ 音频切片第 0 秒，**每条片段都要用 Whisper 对词重新量偏移**；切音频时要在前面多留约 1 秒。
- **480p 足够用**（风格化之后看不出和 720p 的差别）：2.0-fast 480p 6 秒一条 2.25 元。
- **唱跳和非唱跳分开处理**（09-28 定的）：只有唱跳镜头要上传音频、对口型；剧情、表情、特写这类非唱跳镜头**不传音频、不管口型**。**唱跳镜头要拍全身、做大动作**（舞步、转圈、跳起、甩手），别都做成视觉小说那种点头眨眼的小动作；关键帧也要画全身。模板见 [提示词.md](提示词.md) 的〇节。
- **唱跳片段的原唱保留情况（09-29 用 Whisper 逐词对齐实测更正；之前记的「第二、三部分全被重唱」「p3s1 连歌词都唱错」是错的）**：
  - 完整保留原唱，只是开头被裁：s6 舞台服（整体偏 0.94 秒）、p3s1 回形针（整体偏 0.68 秒）。
  - 保留原唱，但**中间或结尾自己多唱了一段**：p2s6 楼顶（开头裁掉约 2 秒；"boom" 后面多了一句 "it's a boom"，之后整体再往后推 0.9 秒；结尾又续唱了一句）、p2s10 跳舞毯（开头裁掉约 2.4 秒，结尾多唱一遍 "repeat now"）。
  - 局部被挤压：p3s2 出拳（"learn to disobey" 被压缩，前后偏移差了约 0.9 秒）。
  - 真正部分重唱：p3s3 点赞（开头多唱了一句，结尾整句没唱）。
  - 注意：**波形互相关低（0.1–0.3）不等于被重唱**。开头裁得多、中间插了一段，互相关也会失效。判断重唱要逐词对齐看（做法见下）。
- **全身大动作和精确口型目前很难兼得（相关性，还没做对照实验）**：原唱保留最完整的 s6、chorus1 都是**半身、小动作**，提示词写的是 `precise lip sync to the audio`，而且提示词较短；第二部分起按新规矩改成「全身大幅舞蹈 + 逐秒舞步」以后，插段、挤压、重唱都出现了。但同一天、同一种写法的第三部分三条，结果也从完好到重唱都有，所以也有抽卡的成分。**需要看清脸、对口型的镜头，用半身 + 小动作 + `precise lip sync` 的写法单独出。**
- **我们有原曲当配乐，视觉卡上点就行**：成片的音轨整条换成原曲，Seedance 自己的音轨不用。口型只在脸大、看得清嘴的镜头才要紧。**唱跳是全身镜头时，脸小、口型对不上看不出来**：用 8fps 细联系表找动作帧（跳起最高点、转圈起点），把它们对到重拍上定 clip0，比对词更有用。
- **会重唱音频**：第二批两个片段都没照原曲走，吞词、压缩节奏（副歌丢了 "P(DOOM), 'cause the"，开场丢了 "ChatGPT"）。第一次副歌却保留了原曲 → 怀疑是"音频驱动"和"音频参考"模式的区别，下次先确认。
- 波形互相关失效时（corr 0.08–0.30），**改用 Whisper 对比同一个词在两边的时间差取中位数**，比较稳（开场实测 0.98 秒，副歌 6.42 秒）。把两边的词序列用 `difflib` 对齐，逐词列出「片段比原曲早 / 晚多少」，哪里被裁、哪里多唱、哪里挤压，一眼就能看出来。
  - 做法：用 Whisper（mlx-whisper，large-v3-turbo，开词级时间戳）分别转写**片段自带的音轨**和**提交用的音频切片**，同一个词在两边的时间差就是偏移。
  - **唱词被压缩时，每个词的偏移都不一样**（第一部分 s1 从 1.1 秒漂到 0.7 秒）。要按用途选锚点：对口型的镜头对齐最要紧的关键词，其他情况取中位数。
  - **看不到嘴的镜头（眼部特写、背影），偏移可以随便挪**，直接把画面里的动作对到重拍上。第一部分 s9 的红眼比提示词写的晚了 1.1 秒，就是挪偏移解决的。
- 口型：原曲保留时，长元音（DOOM / FOOM 的 O 形）能准确落位；重唱时口型跟着它自己那版，只有和原曲一致的后半段能对上。
- 画风跟参考图走得很紧：PC-98 关键帧进去，出来的还是 PC-98。**提示词写"limited animation / held poses"，再逐秒写动作**，重拍动作能卡在 ±0.2 秒以内。

### 4. 代码端的关键设计

- **调色板每个镜头算一次后锁死**（k-means 抽样全片），不逐帧重算 → 不闪。
- **用 Bayer 有序抖动，不用 Floyd-Steinberg 误差扩散** → 画面一动，误差扩散的网点会整片重排、像在沸腾。
- **HUD 在量化之后用调色板原色画，关抗锯齿** → 画面层严格只有 16 色。扫描线是放大后的显示效果。
- 画面层"一拍二"（12fps），HUD 层 24fps → 日式有限动画的节奏。
- 闪白、转场、暗场全部用 **Bayer 网点溶解**，不用透明度混合，更像 PC-98。
- 底片已经自带墨线时，**不要再用代码描线**，否则会出双线（试过 Canny 找边描线，后来去掉了）。
- 16px 像素字体放大成冲击大字时，遮罩要按 `getbbox` 算高度，否则字的底部会被切掉（早期 P(DOOM) 读起来像"P(ПООM)"）。
- **只在少数几帧出现的关键色，会被 k-means 挤出调色板**（红眼、电路板的青和红、推近时的肤色，不加的话脸会发黄）。遇到「某个颜色突然没了」，先给这一段的调色板硬塞几个名额（`ACCENTS[段名]`）。名额有限，塞太多会把别的颜色挤掉。
- **变速（`WARP`）只用在不对口型的地方**：对口型的镜头一变速，嘴就对不上了。
- **段落开头的网点溶解，会用超出上一段范围的时间去取上一段的画面**：片段会自动停在尾帧，但代码镜头要自己能处理越界的时间，不能报错。
- 代码镜头还没写好或者运行出错时，引擎自动换成 TODO 占位画面（`mv.load_code`），整条时间轴照样能先跑通。分工并行时很有用。

### 4b. 参考拆解：PDoomVideo 源码（学原则，不照搬做法）

JohnHeibel/PDoomVideo 是同一首歌的另一版 MV：水彩绘本风，全部用 p5.brush 代码绘制，由 Opus 自己写分镜、再派子代理按章节并行制作。它的画风和具体镜头我们不照搬，**我们要有自己的想法**，只学背后的方法：

- **先有分镜，再动手。** 先定一个贯穿全片的点子，给整部片一个起点和终点，再逐句写镜头。分镜里要写清楚**每个镜头怎么转到下一个**，别等拼接时才想转场。分镜也是省钱工具：能先分清哪些镜头值得花钱用 Seedance（Claude 的表演和表情），哪些可以全交给代码。
- **一句歌词，一个视觉点子。** 每句都要有画面上的「梗」，而且每个镜头里都要有事情发生，不能只是摆拍。
- **反复出现的东西要逐步升级。** 同一个场景、道具或数值（比如 P(DOOM)）在每段副歌里回来时都更夸张，全片就有了推进感。能放进画面里的东西，就别做成悬浮在画面上的界面元素。
- **字要放在对的地方。**（PDoomVideo 的原则是「少放字」；09-28 看了参考片以后，改成更密的大字排版，这里调和两者）笑点主要靠画面和表演来讲；大字给关键词和重拍，爆发段可以密到逐词砸，抒情段要少，别让字把画面占满。做法见核心经验 8「画面密度」。
- **群演也要有戏。** 整齐划一的动作里放一个跟不上节奏的，笑点就来了；情绪要有转换的过程，不要直接切表情。
- **每个段落有自己的主色调**，全片排成一条色彩曲线。
- **做完自检**：看联系表、逐帧看关键动作、放大看脸和手。
- **每帧只由时间决定**（Claude 的判断）：理想状态是任何一帧都能单独算出来，这样可以并行渲染，也能直接跳到某一秒预览。live98 现在的彩带和爱心是逐帧往下算的，6 秒的片段没问题。**等镜头超过 15 秒左右、或者要并行渲染时，再把粒子改成按时间直接算**（用固定随机种子加上出生时间，写成解析公式）。

### 5. 关键帧构图约定（给 HUD 留位置）

底部 1/5 留给对白框（放桌面、栏杆这类简单的东西）；冲击大字放在左上或顶部，留空天空或墙（09-28 起 P(DOOM) 改成画面里的实物，右侧不用再给仪表留位置）。人物偏右时，冲击字统一放左边。

### 6. 踩过的坑

- **ffmpeg 切片**：`-ss` 放在 `-i` 后面时，`afade` 的 `st` 按原曲时间算 → 切出来整段静音。Seedance 收到静音就自己编了一首歌，白烧一次额度。**切完必须跑 `volumedetect` 加 Whisper 复核内容。**正确写法是 `ffmpeg -ss A -to B -i in.mp3 -af afade=...`。
- 暗场底片里皮肤饱和度极低（C≈10），和白衣服几乎一样，只能靠**色相**区分（皮肤暖，衣服阴影冷）。还要按帧做亮度归一化和白平衡（trace98 里有）。
- 系统自带的 ffmpeg 没有 `drawtext` 滤镜，文字一律用 PIL 画。
- Hugging Face 下载模型走 SOCKS 代理，需要装 `socksio`。
- **DotGothic16 缺不少简体字**（每、势、两、现……），画面里的字用日文或英文，要写中文先试渲染一下。实在要显示简体字（例如中文房间的纸条），改用系统字体 `/System/Library/Fonts/Hiragino Sans GB.ttc`。
- **找生图提示词原文**：每个素材文件夹里的 `index.jsonl` 记着提示词、参考图和模型（例如 `素材/关键帧/index.jsonl`）。Seedance 的任务记录在 `镜头/index.jsonl`。
- **生图审核**：短裙 + 高踢腿在输出阶段被拦（moderation_blocked），换成出拳就过了。唱跳姿势避开抬腿、下摆翻起这类构图。
- **放大的像素字要按字形的实际外框建画布**（`F16.getbbox`）：09-30 好感度框的「好感度」画布高度写死 18，放大后字的下半截被切掉。对白框「クロード」名牌是同一个原因：DotGothic16 字形上沿自带约 4px 空白，按 `y0-10` 画会往下掉出名牌（已修，`mv.hud`）。
- **`crop()` 碰到画面边会把裁切框推回来**，按原中心换算的特效坐标就偏了（09-30 王冠落地的闪光跑到左边）。特效坐标要按实际裁切位置算。
- **拉镜带回弹过冲时，放大倍数会掉到 1 以下**，裁切框超出画面、整帧变黑。算完倍数要 `max(z, 1.0)`。
- **zsh 里装在字符串变量里的一串参数不会自动拆开**（`R="--ref a --ref b"` 会被当成一个参数），要用数组 `R=(--ref a --ref b)` 再 `"${R[@]}"`。
- **改图容易把画面里的小字弄丢**（换装 b、c 的便利贴只剩空白黄纸）：要么提示词里点名保留，要么从底图把那块贴回去。
- **DotGothic16 没有「▶」**（画出来是一个带叉的方框），地图光标原来一直是方框。三角箭头用 `poly` 手画。用冷门符号前先渲一下看。
- **numpy 负下标会绕到画面另一头**：物件画到画面上方出界时，`img[y:y+h]` 的 y 是负数，会把东西画到画面最底下（GPU 的金手指跑到了对白框后面）。切片前先 `max(…, 0)`。
- **窗户 / 频谱这类按音乐动的东西直接读原曲**：`props.spectrum(t, n)`（ffmpeg 解码一次缓存，FFT 取对数频段，纯函数）。串烧里重播旧背景时，`backdrops_p4.replay` 会把真实歌曲时间放进 `L.REAL_T`，频谱跟着当下的音乐走，不跟着被重播的那一秒。
- **前景层会挡住主角**：舞台前排观众原来画在人物前面（想做纵深），结果挡住 Claude 的头发和裙子，像穿帮。09-30 改成画在人物后面（`live98.Extras.cast` 最后一项 `False`）。主角身上别压任何前景群演。

### 6b. 节奏与接缝（09-28 第一部分）

**节奏要干脆，别让人等**
- 第一部分开头曾经在张嘴的首帧上定格 0.6 秒，一眼就能看出来；改成放慢播放补位也不自然。最后的做法：加载画面可以多停一会儿，拉远只用 0.2 秒，落到全景的那一刻正好开唱，片段原速播放。
- 开场和转场都照这个思路：**宁可前一段多停一会儿，也别让人物定格或慢放着等唱词**。
- 注意区分：核心经验 8 的「滞空」是为了表现力量、特意在最高点停住，和「为了凑时间让人物干等」是两回事。

**有小瑕疵可以接受，但接缝必须藏住**
- 两批 Seedance 的衣服、姿势、光色对不上（女仆献软盘 → 怪物大嘴），直接接上明显断开。改成「推进屏幕 → CRT 故障 → 从大嘴特写拉回」以后，小瑕疵还在，但不影响观看。
- **两批素材接不上时，找两边都有的东西做匹配剪辑**（这里是屏幕和大嘴，几乎在画面同一个位置），再用故障或闪白盖住换片的那一帧。

### 7. 第三阶段（09-28 第三部分 v1 → v2）的定论

**抽帧浓度（用 `hold_demo.py` 六格对比后定的）**
- **默认用一拍三 8fps**（片段帧号取 `i - i % 3`），最对味；**一拍二 12fps 也可以**。
- **「每拍一个姿势」停帧（`mv.HOLD`）太硬，只当闪回、重拍点缀偶尔用**，别整段铺。用在特定的展示场景很好，有定格动画的观感，见核心经验 8「一拍一个姿势」。
- 注意区分：一拍三是**均匀抽帧**，动作还是连续的，只是更顿；HOLD 是**挑关键姿势再停住**，会把中间的动作整段删掉。

**静态 CG + 有限动画效果出奇地好**（打火机点火、蓝调酒吧）
- 做法：一个镜头出 2–3 张同构图的关键姿势（改图），按唱词硬切或短溶解，加上缓推、光点或火星粒子、换光（冷光 → 火光闪一下），这样就够了。
- 非唱跳镜头优先这样做，比 Seedance 便宜，也比代码画的好看。**代码画的动物、角色显得廉价**（v1 的代码龙猫后来改成了生图）。
- 改图会轻微推拉构图，用 `codeshots_e.cg_aligned` 对齐回底图；原图很暗的（打火机）量化前要先提亮。

**节奏**
- **「一句两镜、一词一镜」只用在爆发段**。抒情段（Gato）v1 切得太快，v2 改成 7.5 秒 4 镜，镜头之间用网点溶解。先看段落情绪再定切镜密度。
- **嘴型别按音节开合**：v1 酒吧 1.4 秒换了 9 次嘴型，显得很鬼畜；v2 一句只换 3 档（半开 → 闭 → 张大唱到底）就很好。

**衔接**
- **两部分的接缝要逐像素接上一部分的末帧**：第二部分停在「全黑 + 放大 4 倍的 NIL」，第三部分 v1 只露一帧 NIL 就硬切，接缝一眼可见。v2 用同位置、同大小的 NIL 做变形（N、L 溶解，I 拉成猫的竖瞳）。**做新一部分之前，先渲出上一部分的最后一帧看清楚。**

### 7b. 工作方式

1. **生图不满意，先说明再重画**：第一版不满意时，先说清楚哪里不对、打算怎么改，确认了再重画。画面取舍是审美决定，模型眼里的「翻车」不一定真是翻车。Seedance 花钱，每条都先报计划再提交。
2. **非唱跳镜头不对口型，也不放连续的 AI 动作**：这是 AI 感的主要来源。改成静止帧（旧 Seedance 片段抽帧 / 生图 CG）按唱词硬切，动的部分交给代码（推拉、抖动、粒子、界面）。
3. **「定住」就要真定住**：两次推拉之间画面必须完全静止。v12 两级推镜之间视频还在往前播，一眼就能看出来。
4. **拿不准的决定先出对比再挑**：把改动拆成开关一项一项叠上去（A→F），先出同一帧的静帧对比，再出动态对比，最后换一个不同类型的镜头（比如全身舞蹈）再确认。改引擎、画风这类影响全片的东西，别直接跑全片——舞蹈清晰度第一次就是直接改完，效果反而变差，拆开才看出是「保墨线」和「网点调淡」两项拖了后腿。
5. **改某个小镜头，先出一小段 demo，确认了再合并进全片**：例如开场落地时间，先用 `part1.py --from 0 --to 5.8` 出几秒预览，确认了再重出整部分、拼全片，省得每改一处都跑十几分钟。
6. **改动先出关键帧截图，别急着渲染**：每改一个镜头，挑 4–6 个关键时刻出量化后的联系表（`codeshots_x.py --sheet 名字 t1,t2,… --out x.png`），看图改完一轮再统一渲染、拼全片。
7. **牌子、屏幕上的像素大字，画之前先算高度**：`draw_text` 放大 n 倍字高 15n 像素，比牌子黑底高就会被下半截切掉（全片三块牌子都中过招）。数字一律过 `props.digit_scale(可用高度, 想要的倍数)`。

### 8. 第四阶段（09-29 第四部分）的技术手法

> 下面是这一轮实际用到的做法，**是工具箱，不是规定**：每个项目、每个段落的情绪不一样，先想清楚想要什么效果，再挑合适的工具，觉得不对就换。
> **新做法先做短 demo 验证，确认了再铺开**：滞空、赛璐璐局部动画、精灵表都是先出几秒的对比片验证的，比直接改正片省事，也不会白做。

**画面密度：切镜、景别、大字、插卡**（09-28 第三阶段对照参考片定的方向，第三、四部分验证过）
- **一条片段切出几个景别**：同一条 Seedance 用数码推拉硬切全身 → 脸 → 眼睛，一条素材当两三个镜头用，不花钱。480p 的片段推到 2 倍左右，还是 PC-98 那种颗粒感，能用（`CAMS`，或者把同一个片段拆成几段、各挂不同的推拉）。
- **切镜密度跟着段落情绪走**：爆发段、高潮句可以一个词一个镜头；抒情段要慢，镜头之间可以用网点溶解（见核心经验 7「节奏」）。
- **大字排版**：关键词做成巨大的描边立体字压在画面上；**每个段落换一种字效**（描边立体、故障、霓虹管、竖排日文、空心细字），带入场动画（弹入、横扫、砸下、抖动）；位置跟着构图走、避开脸，不要固定在一个角（`mv.slam2`）。
- **开场剧透卡、笑点插卡**：开头半秒先闪一张副歌的造型卡再回到正片；每段可以插两三张 1 秒左右的小插卡，讲一个画面上的梗。梗要自己想，别照搬参考片的。

**节拍感可以放在剪辑上，不一定要放在人物身上**
- 这一轮人物全程是引擎默认的一拍二（`live98.Character.get` 的 `i - i % 2`），没用 `HOLD`。节拍感来自切镜：嘉宾一拍一个，舞蹈串烧先两拍一切，最后加速到一拍一切，镜头里的动作保持连续。
- 想要「卡点」感时，可以先试着在镜头之间卡拍，再考虑镜头内部停帧；两者也能混用（第三部分的 `HOLD` 在爆发段效果也不错）。

**一拍一个姿势（`mv.HOLD`）：定格动画的观感**
- 人物只取关键姿势，每拍换一张并停住（跳到最高点、手伸到底这类转折点），中间的动作整段省略，看起来像定格动画或摆 pose 拍照。
- **适合「展示」性质的场景**：亮相、摆造型、角色介绍、有意做成定格动画风格的段落、重拍上的闪回。整段舞蹈都这样铺会显得硬，但放在需要一个个姿势被看清的地方反而很有力量。
- 用法：`HOLD[片段名] = dict(every=1)` 按拍自动挑最静的一帧（`every=2` 两拍一个）；想精确控制就写 `keys=[(歌曲时间, 片段时间), …]` 手挑姿势（先看 8fps 联系表）；`bounce` 是换姿势时往上弹的像素。舞台和特效照常逐帧走，只有人物停。
- 素材要求：Seedance 提示词里写 `strong clear held poses that snap from one to the next on the beat`，动作越大、姿势越分明越好挑。
- 可以和别的办法搭配：一段里大部分用一拍二连续动作，到亮相那几拍切成 HOLD；或者 HOLD 配上切镜时的 `drop` 特效，让每个姿势都「砰」地落下来。

**赛璐璐式局部动画：身体定住，只有头发 / 手在动**（09-29 拆参考片 12 秒后试出来的，两种画法都验证过，模板在 `提示词.md`「赛璐璐式局部动画」）
- 这是赛璐璐动画最典型的质感：身体是一张不动的画，只重画要动的部分。静与动的对比本身就很好看，也很「90 年代」。
- **重要镜头、想要流畅 → 视频版**：Seedance 首帧给底图，提示词明确写「身体是一张定住的赛璐璐、点名哪些部位全程不动、只有头发在动、每秒 12 张」。实测它真能做到：腿部帧差是噪声水平，画面自己就是每两帧一张，头发过渡连续流畅。（之前推测参考片这一段是后期合成的，实测后推翻：视频模型可以直接生成。）
- **背景角色、预算紧、想要一张张画的顿挫感 → 生图版**：同一张底图改出几张「只改头发 / 手」的变体，合成时只取变化的那一块贴回底图，身体逐像素不变。张数决定流畅度。
- 拿视频硬把下半身锁在一帧上（`technique_demo.py` 的第一段）效果不好：接缝处和整体节奏都会露馅。想要这种质感，从生成阶段就做成「身体本来就不动」。

**力量感来自时间的安排，不一定来自动作本身**（09-29 拆参考片 24 秒、46 秒，并用 `technique_demo.py` 试过）
- **滞空 + 冲击连击**：动作里最有力的那一刻（跳到最高点、拳头伸到底）值得停久一点，让观众看清；紧接着在重拍上用硬切、闪白、大字把它「砸」下来。蓄力 → 停住 → 爆发，这个节奏比动作本身快不快更重要。
- **定住的帅气姿势 + 背景在动**：一个姿势足够好看的时候，人可以几乎不动，速度、方向、情绪都交给背景（速度线、光环、镜头推拉、抖动）来表达。静的人配上动的世界，反而更有冲击力，也更省素材。
- 两招都不挑素材，现有的片段、CG 都能用。关键是想清楚这一刻要观众感受到什么，再决定人动多少、世界动多少。

**精灵表 → 按拍换姿势（不花钱的「会跳舞的配角」）**
- 来由：09-29 拆参考片（@pleometric 的 90 年代偶像版，拆解材料没收进仓库）发现它用了两种做法：主角跳舞是 Seedance 视频抽成一拍二（片尾写着 `MOTION REFERENCE: Seedance 2.5`）；尾奏的嘉宾（蛇怪、龙猫、黑猫）只有两张姿势，平时停在 A，每拍闪 B 两帧。
- 我们的试验（`scripts/sprite_demo.py`，用法见「脚本」一节，出 mp4 / GIF 演示片）：**一张精灵表一次生成 4 个姿势**（同一次生成里比例、线条、配色最一致，比分几次改图稳），切开后保留各自离脚底线的高度，放在代码画的背景上，按拍网格换姿势，换的瞬间挤扁 2 帧再弹回。一拍一换已经很灵动，半拍一换更欢。
- 精灵表提示词的要点：同一行、同样大小、互不重叠、**脚踩同一条水平线**（跳起的姿势写明只离开一点）、纯色空背景（gpt-image 这次直接给了透明底 PNG）。原文在 `提示词.md`。
- 可以再往下试的方向（还没做）：6–8 个姿势排成左右对称的舞步；学参考片停在基础姿势、每拍闪一下；叠加 live98 的拍点光效和影子弹跳。
- 局限：画风一致只靠同一次生成，换得越快，姿势之间的细节差异越明显；不适合做连续平滑的动作，那种还是交给视频模型。GIF 的帧时长按 10 毫秒取整（24fps 会变成 25fps），要配乐就出 mp4。

**分层帧率**
- 人物 12fps，舞台、粒子、光、运镜、HUD 24fps，这是日本动画的常见做法：人物有手绘的顿挫，画面整体仍然顺滑。
- 引擎本来就是这样分层的；想让人物更顿（一拍三）或更顺（逐帧），改人物层就行，不影响其他层。

**切镜那一刻的特效可以代替停帧打拍子**
- live98 的 `drop` 不一定只用在副歌开头。第四部分串烧把每段的 `drop` 设在切点上，每一刀自带闪白、彩带和推镜回弹。
- 注意别叠两层闪白：`HITS` 和 `drop` 撞在同一时间会白太久。

**同一条 Seedance 可以挂几个名字反复用**
- `CLIPS` 里同一个文件配不同的 clip0，就能从片段里任意一段开始播。第四部分的舞蹈串烧全部来自以前没用过的余量（约 27 秒），一分钱没花。
- 每条片段用掉了哪几秒，查各部分配置里的 `CLIPS` 和 `TIMELINE` 就能算出来。余量适合留给收尾、蒙太奇、回顾这类段落。
- 前几部分的背景函数用 `backdrops_p4.replay(f, a, t0)` 包一下，就能从当时的时刻重播，拿来做回顾很方便。

**变速（`WARP`，live 段也能用）**
- 适合把一段现成的动作对齐到歌里的几个点，例如谢幕按四声 oh 分段变速。变速后仍按一拍二抽帧，快的地方反而显得利落。
- 分段越多越好对齐；单段快过三倍左右会开始像快进，可以视情况调整。

**长镜头和密集切镜形成对比**
- 「for show?」那段从布景拉到显示器、再扎回屏幕，一镜到底，全程逐帧计算、没有转场。放在密集切镜的中间，前后反差会让情绪起伏更明显。
- 屏幕套画面的技术要点：`codeshots_g.screen_view` 让生图把屏幕画成纯绿，按 HSV 找到这块区域；16:9 的画面放进 4:3 的 CRT 时上下留黑边，屏幕铺满画面时就能和上一镜逐像素接上；推近时按放大后的尺寸直接贴图，不会糊成马赛克。
- 屏幕里套自己（德罗斯特效应）：让画面映射的不动点保持不动，推近倍数取 `(1/s)^frac(u)`，就能无缝循环（`backdrops_p4.droste`）。

**接缝**
- 下一部分开头最好沿用上一部分最后一段的同一个画面源、同一个停帧设置和同一个调色板（`PALETTE_SPAN` 指定调色板的抽样区间），这样第一帧会和上一部分的末帧一致。
- 要从上一部分的状态过渡出来，可以用 `TILT` 的四项写法（起始角度 → 结束角度）这类平滑过渡。

**画面里的文字**
- 片尾字幕做成滚动，容易压住画面主体。做成右下角一张张的小窗口卡片（`codeshots_g.credits`），跟着切镜换，干净很多。
- 字要画在量化之后（`OVERLAY` / HUD），只用调色板原色，才不会被抖动打散。

**生图**
- 素材里已有的房间、道具，拿原关键帧当参考图重画，比重新描述稳得多（第四部分的深夜桌子就是这样对上第一部分的房间和便利贴的）。
- 一张图里塞太多指定物件，容易漏画。梗多的时候拆成两张。
- 原图是绿幕的素材（例如蛇怪），单独拿出来用之前，要先照它原来那一部分的层次合一个背景（`backdrops_p4.basilisk_cg`）。

**（09-30 第一部分重做）空房间底板 + 人物单独一层：背景不动，只有人物动**
- 做法：生一张没有人的空房间底板（改图去掉人物和道具），每张姿势图用 rembg isnet-anime 抠出人物层（遮罩缓存成 `*.alpha.npz`），叠在同一张底板上。换姿势的那一刻只让人物挤扁回弹、左右抖两下、冒几颗星，电脑和房间逐像素不动（`codeshots_p1r` 的换装三连、鞠躬）。
- 旧 Seedance 片段里的关键姿势也能这样抠出来叠上去（鞠躬：s4 第 56 / 60 / 64 帧，一帧一张快速鞠下去，到底挤扁回弹），和新画的姿势共用一张底板，背景不会跳。换姿势时加一个「下蹲衔接」，效果很好。
- **立绘感从哪来**（以鞠躬为例）：①**视频只当姿势库**，挑 3 帧定格，中间的连续动作全丢（AI 感主要在连续动作里）；②**遮罩二值化**（`np.where(m > 127, 255, 0)`，不留羽化），人物像剪下来贴上去的纸片，也就是视觉小说的立绘；③**背景是静止 CG**，不用视频原背景，于是变成「立绘叠在背景 CG 上」；④落地的弹性交给代码（以脚底为基准压扁 8% 回弹 + 冒星），不交给视频；⑤最后整帧锁调色板量化，把视频抠像和生图 CG 的质感拉平。
- 细节：挑帧前先看抠图结果，有的帧 rembg 会丢道具（s4 第 52 帧托盘没了，换姿势时托盘会一闪消失，所以弃用）；视频里人物旁边的道具（显示器）用 `m[:, 440:] = 0` 这种硬裁剪挡在人物层外面。
- 同一个思路后来用在 FOOM 蓄力段（`codeshots_foom.py`）：人物是一张不动的立绘，动作全交给镜头（拉镜、升降台）、灯和群演。**Seedance 动作好、但整段播放 AI 感太重的片段，都可以这样挑几帧来用。**
- 两张图逐像素对得上时，直接相减就能抠出差异（王冠 = 有王冠图 − 无王冠图）；对不上时别用差值（改图常把背景另一半重画），用 rembg。

**格斗游戏式的斜切特写（切入）**
- 画面中间一条斜着的画框（左低右高），框里是角色特写，一个词换一张，每张从侧面「唰」地切进来（带回弹）；画框外是背景画面压暗、叠红色放射速度线（每 3 帧换一批）。最后一个词画框推近到眼睛、一直抖。
- 特写用生图（设定图 + 最好看的那张当参考），不用视频模型的脸。实现在 `codeshots_p1r.scene_cut`。

**冲击帧（インパクトフレーム）**
- 画面二值化后黑白反相，再用 Canny 描一圈红边，只放 2 帧（约 0.085 秒），配一下震屏。
- 用来填空拍（没有唱词、但有底鼓的那一拍），也能放在一段戏的头尾把它框起来（C 段 16.63 变速第一拍、18.43 亮相）。实现在 `codeshots_p1r._impact`。

**舞蹈（live）段的清晰度：少重采样**（09-30，看了 A–F 静帧和两段动态对比后定的）
- 糊的根源是**重采样次数太多**：人物先 854→640 缩一次，再 ×0.82 双线性变换又缩一次；运镜每帧 1.03 倍 + 0.6° 摇摆再插值一次。每次插值都在抹细节。
- **人物从原图一次缩放到位**（`live98.Character._sharp`）。
- **运镜和清晰兼得**（`live98.Character.get2`）：背景（渐变、光束，糊了看不出）照旧跟运镜插值；人物层在 2 倍分辨率（1280×720）上跟着运镜变换，再 `INTER_AREA` 缩回 640，插值带来的糊少一大半。
- **前景跟着运镜**：先照老顺序合成整帧，记下前景（观众、彩带）改动过的像素，把整帧和这张前景遮罩一起跟运镜变换，最后只把人物换成 2 倍层，前景再盖回它上面。只把前景画在运镜之后的话，drop 推镜时前景会原地不动，很怪。
- **轮廓光按新的人物轮廓算**：高清人物层的边缘比旧层收得紧，轮廓光还按旧轮廓算，就会在人物边上露出一圈紫边。
- **被否掉的两条**：「保留墨线」（原图暗线强制画成 ink 色）会把头发暗部画成死黑；网点强度从 36 调到 20 会丢掉 PC-98 的颗粒质感。
- 做法：先把几种方案做成环境变量开关并排出对比，定下来以后再把没选中的分支删掉。

### 9. 检查与收尾的小技法

**分段做、整片拼：视频直接拼，音轨整条换成原曲**
- 全片按段落分开出片（每段几十秒，改一段不用重渲整片），最后再拼起来。只要各段是同一套编码参数，视频就能直接复制拼接、不重新编码，几秒钟就拼完。
- 音轨不要用各段自带的，整条换成原曲：各段的音频是按段切的，接缝处会有空隙或咔哒声；换成原曲，整片的声音天然连续。
- 做法（列表文件里写绝对路径）：
  ```
  printf "file '%s'\nfile '%s'\n" /绝对路径/前面几部分.mp4 /绝对路径/新的一部分.mp4 > list.txt
  ffmpeg -f concat -safe 0 -i list.txt -i 素材/音频/PDoom_完整版.mp3 -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -t <全片秒数> 成片/xx.mp4
  ```
- 拼完抽接缝前后几帧看一眼：视频直接复制拼接，接缝画面接得上接不上，全看上一段末帧和下一段首帧（见核心经验 7「衔接」）。

**切镜统计：用数字看节奏**
- 切镜密度是节奏感最直接的指标，光靠感觉容易偏。数出切点，就能比较不同段落、不同版本、参考片各是几秒一镜。
- 做法：每帧转灰度、缩到 160×90；算相邻两帧的平均差；差值 > 25、且大于前后各 6 帧差值中位数的 4 倍，就算一个切点。第二个条件用来排除运镜、闪光这类持续变化的镜头。
- 参照：参考片前 38 秒约 1.4 秒一镜；我们第一部分约 3.5 秒一镜，第三部分约 1.1 秒一镜。抒情段和爆发段本来就该差很多，数字只是帮忙确认「想要的节奏」有没有做出来。
- 同一个思路稍微变一下，也能拆参考片：只盯某个区域算帧差，看隔几帧变一次（判断一拍几）；拿某一帧和后面各帧比（判断是不是停住的画）。

**测量时避开背景干扰**
- 背景在转、灯在闪、网点在抖的镜头，整帧帧差每帧都很大，看不出人物有没有换画。要只盯人物所在的区域，先模糊、缩小再比（只看大块形状，忽略抖动网点和扫描线）；或者身体、头发、背景分开算，一眼就看出哪一层在动。
- 区域框完先截图确认框对了：09-29 拆转椅那一段，本来想测脸，框到的却是手臂，一开始的结论差点就错了。

**联系表：一行 ffmpeg，不用写脚本**
- 看停帧（连续 24 帧排成两行，数同一个姿势重复了几格）：`ffmpeg -ss <秒> -i 视频 -vf "crop=<宽>:<高>:<x>:<y>,scale=200:-1,tile=12x2" -frames:v 1 x.jpg`
- 全片总览（每 0.5 秒一格）：`ffmpeg -i 视频 -vf "fps=2,scale=320:-1,tile=8x10" 总览_%02d.jpg`
- 自检自己的成片也用得上：每一版出完先抽一张联系表，比从头看一遍快，也更容易发现某一格的问题。
- **量坐标**（屏幕四角、人物脸的位置、道具中心）：在帧上画 64px 的网格再看图，读数比凭感觉估准得多。

### 10. 派子代理并行做代码镜头（有必要再派）

> **子代理很费 token**：每个子代理都要从零开始读项目、读接口、读素材，主 agent 还要再读它们的汇报。第一、二部分派过（效果不错），第四部分全是主 agent 自己写的，效果也差不多。**默认自己写，确实有必要才派。**

**什么时候值得派**
- 代码镜头多，而且**彼此独立、各讲各的梗**（第一、二部分那种一句一个视觉双关，镜头之间没有共用的机关）。
- 赶时间，几个镜头同时开工能明显省时间。

**什么时候别派**
- 镜头之间有连续的机关，要一气呵成（第四部分：布景 → 显示器 → 空房间 → 扎回屏幕 → 结尾关机，都是同一套「屏幕套画面」）。拆给几个子代理，接缝和手法很难对齐。
- 几个镜头要共用同一套手法、配色、组件（演职员表卡片和嘉宾名牌）。
- 镜头不多，自己写也就一两个小时的事。

**要派的话**
- **先写好公共接口，再派活**：`part1_lib.py` 文件头写清约定（`scene(t)` 是纯函数、只画全彩、给 HUD 留出区域），几个子代理各写一个文件，同时开工，接进时间轴一次就通了。
- **提示词里写死三条规矩**：只准改自己那一个文件；不准生图、不准跑 Seedance；联系表必须亲眼看过再汇报。
- 素材里的坐标（投信口、面具中心、屏幕四角）让子代理自己去量，量得很准。
- 子代理只能改自己的文件，它们提出来的需求（例如某一段要单独锁调色板、保留某几个颜色）要由主 agent 在配置里配合处理。
- 子代理没写完时，时间轴里的占位画面（见核心经验 4）让整条片子照样能先出片检查。

### 11. 代码镜头的「精细」和「一直在动」（10-19 花絮段）

花絮段做到了两点：场景精细、画面里的元素一直在动——中文房间的箭头、怪物的自然呼吸、收据自然探出、扫回形针的动作、精灵表的过渡动画。**这是理念，不是清单**，下面是总结的做法：

**精细 = 让每一块面都「有东西」，不是多画几样东西**
- **每个面都有体积**：墨线框 + 底色 + 上 / 左一条高光、下 / 右一条暗边（`codeshots_h.bevel`）。纸箱、桌子、镜框、转椅靠背都这么画，一下就从色块变成物件。
- **材质靠小而规律的重复**：瓦楞纸的胶带和侧面、木纹的短横线、榻榻米包边和草纹、百叶窗、墙纸菱形、幕布每一褶三档明暗。不用画细节，画「纹理的节奏」。
- **有光源就有光晕**：灯泡、柔光箱、霓虹、聚光，一律用 Bayer 网点晕一圈（`glow` / `neon`），PC-98 味道和氛围同时有了。
- **分前中后景**：前排纸箱挡住蛇怪下半身、真身压暗放在镜头前当前景。层次比细节更「贵」。
- **藏会讲故事的小物件**：凉掉的咖啡、坏了一闪一闪的灯泡、白板上的「(maybe)」、碟子里还剩两条小鱼干。观众扫一眼就知道这里有人生活过。
- **杂场景先锁主角色**：元素一多，16 色里 k-means 会把小面积的主角颜色挤掉（新蛇怪一个紫都没剩）。主角的关键色从原图里取，写进 `ACCENTS`。

**一直在动 = 一拍里也有小故事，且每个动作都「自然」**
- **画面里至少有一样东西在动**，幅度小但不停：手绘箭头一笔描出来再冒尖、收据从打印口慢慢吐、扫帚来回扫、汗珠往下滑、怪物慢慢起伏像呼吸、灯泡闪、场记板在鼓点上合上。静帧 CG 也靠这些活起来。
- **一拍 = 起 → 变 → 定**：例如修格斯中の人（没采用，但结构对）「风掀开 → 露馅 → 全员僵住」、龙猫「发愁 → 吸肚子 → 弹回去」。0.45 秒也能讲一个包袱。
- **精灵表别硬换帧**：帧和帧之间用挤压 / 拉伸 / 发抖 / 先撑大再回弹接起来，指针、数字这种跟着走的东西做成连续插值。硬切三帧 = 卡；加过渡 = 生动。
- **动作要有「为什么」**：呼吸用缓慢正弦、扫帚用快速正弦、弹出用 `ease_out_back`，不是随便抖。

### 12. 「像素重绘」的味道（10-19）

look 段（背身唱跳 v2 → live98）放大来看，有一种「像素重绘」的味道。对成因的判断（**是推测，没做对照实验**）：
- **底片本身是干净的平涂**：v2 片段来自 PC-98 风关键帧 + 设定图当参考，头发是几大束两档色、墨线清楚，没有渐变和细发丝 → 量化成 16 色后每一束头发都是整块色面，像手点的像素。
- **480p 片段再缩到 640×360、按 Bayer 网点量化**：一个视频像素≈一个画面像素，线条变成一格宽的硬边，不糊。
- **抠图描一圈暗紫外光晕**（live98）把人物从背景里「剪」出来，更像精灵图。
- 结论：想要这个味道，**关键在底片干净（PC-98 平涂关键帧 + 设定图参考）**，不是后期多加什么。

**力量感靠剪辑（10-19 look 段）**：先出不套滤镜的原片剪辑 demo（`look_power_demo.py`，没收进仓库）比来回改 PC-98 成片快。**手法按场景选**（闪白也可以用，像 demo B 那样）：look 段要的是前面原速、转身稍加速（约 1.1 倍）、边转边推近、不闪白不定格；更炸的场景可以用 B 的「落定闪白 + 推一级 → 重拍再推一级」；转身里抠图坏掉的帧，直接用变速跳过（快速甩动本来就该少几帧）。
**白手套叠在舞台灯上会被 rembg 抠丢**：同一条片段重新编码一次，丢的帧就可能变（导出版第 64 帧整条手臂没了，原片只缺指尖）。查法：抠图压暗背景拼联系表逐帧看；补法：静止段用前后 ±2 帧的 alpha 取最大，快速运动段别补（会带残影），跳帧。

**爆炸褪色（10-19 BLUES 后）**：`codeshots_e.scene_face` 炸开以后——人物**保留原画线条和明暗**，被暖黄强光漂白、褪色（想要的效果：「颜色被强光漂白、褪掉，好像光强到把她身上的颜色都抽走了，脸和五官仍然清楚，迎着爆炸那一侧更亮、过曝」）；**已按离炸点距离去色**（`near = 1 - d/560`：越近饱和度越低、越往白提）；身后五层不规则火球 + 放射光 + 网点冲击环；画面碎成斜玻璃片 + 速度线 → 涨白。生图参考用「bleached and faded by the overwhelming glare」这类说法，别写 black and white / silhouette / manga（会画成剪影）。
- 以后可以试：碎片做成可选开关、多做几层（大小碎片叠、角度更乱、每层错开速度不同）。

**30fps 素材的坑**：引擎按 24fps 算片段帧号，外部导出的 30fps 片段会整体慢 1.25 倍（取到的是更早的帧）。外部给的片段先 `ffmpeg -vf fps=24` 转一下再接。

## 音频分析

**这首歌中途变速**：前奏主歌（0–16.2 秒）是 **88 BPM**（拍网格 0.03 + n×0.682）；从 ChatGPT 开始是 **132 BPM**（拍网格 16.632 + n×0.4545）。**21.63–23.89 秒底鼓停（憋气），23.89 秒 drop**，正好落在 "DOOM" 上。

> ⚠️ 测速的曲折：先测出 129，又从副歌片段测出 136，后来改成 88，**三个都不完全对**。之前用来否掉 136 的「拍上 vs 半拍」测试用的是 0.465 秒的网格，比真实的 0.4545 每拍差了 0.01 秒，40 拍就漂移半拍，对比被抹平了。而 88 在那 42 秒片段里得分也不低，因为 88 拍和 132 拍每隔 1.36 秒会重合一次。**正确做法：分段测（变速的歌整段一起测，两种速度会互相抵消），逐个扫拍长（步长 0.0005 秒），每个拍长找最佳相位再比较「拍上 vs 半拍」。**只看底鼓起音列表也很直观：16.6 秒以后，底鼓间隔稳定在 0.453 秒。

## Clawd 群演（素材/ClaudeAnimationBase，MIT）

JohnHeibel/ClaudeAnimationBase 是 PDoomVideo 作者的 p5.js + p5.brush 角色套件，不是图片素材库。Clawd 是程序实时画出来的，自带 31 种情绪、11 种舞步、15 种帽子，全部跟 BPM 走。本地改了三处：`src/config.js` 的 bpm 改成 132（副歌段的真实速度；**现有的 `素材/群演/*.npz` 是按 136 渲染的，跳得略快，需要重新渲染**）、`studio.html` 引入了 `src/scenes/xk_extras.js`、新增了 `xk_extras.js`（6 种造型：派对帽 bounce、耳机加双青荧光棒 roof、蝴蝶结加爱心眼 hop、黄荧光棒 wave、墨镜皇冠 shimmy、猫耳星星眼 spin；纯绿 `#00FF00` 底，`noShadow`，一个循环 8 拍）。渲染器用的是 Playwright 自带的 Chromium（本机没装 Chrome），一帧约 65 毫秒。要加新造型：在 `xk_extras.js` 的 `V` 里加一项 → 渲染 PNG → 运行 `clawd_extras.py`。荧光棒不要用绿色，否则会被一起抠掉。
